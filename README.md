# 小剧场灯光 Cue 排演（Lighting Cue Rehearsal）

一款用于小剧场灯光排演的 Web 应用。录入**灯具**与按演出秒数触发的 **Cue**
（灯具编号、目标亮度、非负渐变时长），所有灯光效果都在浏览器中模拟，**无需连接任何真实灯具**。
支持播放 / 暂停 / 跳转，并实时显示任意时刻每盏灯的实际亮度；发布后生成**不可变演出版本**。
排演人员还可针对已发布版本建立**临时调光记录**，按演出时码追加「覆盖 / 归还」操作，
随时查看任意时刻的**逐灯实际输出**；记录绑定版本快照，草稿修改与新版本发布都不影响既有记录。
此外可在草稿期配置**灯光回路**（正数容量）与灯具的所属回路/正数额定瓦数，随发布一并冻结，
并对已发布版本或绑定它的调光记录做**回路超载预判**：返回查看时刻负载与时窗内严格超出容量的
全部连续区间（精确求根，不做固定步长采样）。
排演人员还可基于已发布版本创建**共享房间**：创建者持控制密钥，其他人凭房间码观看同一舞台与
逐灯亮度；房间固定所选版本，由服务端按墙钟推算时码、到末尾自动停住，刷新/重启/重连均可恢复，
后续草稿修改与发布不影响它。当前主持人可凭控制密钥与房间修订号**交接主持权**：取得仅显示一次、
五分钟有效的一次性交接凭证，接班人凭房间码与凭证领取新密钥（领取与修订号递增原子完成、旧密钥
即刻失效、并发至多一人成功；原主持人再控制即作废，过期/错误凭证与过期修订号均明确拒绝且不
改变控制权）。创建时可选择启用**回路超载保护**：只按固定版本快照中的回路容量与灯具接线，在
播放方向上首个负载严格大于容量的区间左边界自动暂停并返回触发回路与时码，不越过危险段；
未启用的房间沿用原行为。主持人还可按固定演出版本**编排 1～8 段循环排演**：每段给出
非负起止时码与正整数重复次数，提交携带控制密钥与房间修订号，成功后从首段开始、按服务端
墙钟与当前倍速依次穿过各段（段尾立即跳回本段起点或下段起点），全部完成后停在末段终点；
暂停与改速保留进度、从断点接续，手动跳转取消编排。启用超载保护时，超载的段起点会拒绝
整次编排，运行途中抵达超载边界仍自动暂停、不越过危险段。主持人还可在房间预置**讨论停点**：
凭控制密钥与房间修订号提交一组不重复的非负演出时码（不超过版本末尾，空组表示清除），
整组校验后原子替换；播放按服务端墙钟连续经过下一停点时准确暂停并显示原因（自动暂停不
增加修订号，刷新/重启/重连后状态一致），继续播放越过刚触发的停点，循环排演每次重新经过
仍暂停，段尾瞬时跳转不触发被跳过的停点，与超载边界同时抵达时超载优先。主持人还可为暂停的
房间**预约定时启播**：凭控制密钥与房间修订号指定一个未来墙钟时刻（Unix 秒或 ISO 8601），
同一房间只保留最近一次预约、也可取消；到点按现有播放规则从当时断点自动播放（已完成的循环
排演从首段重来），自动启播不增加修订号，启播按绝对墙钟——服务重启或首次查询已晚于预约时刻
时仍按预约时刻起算进度，准确停在先遇到的讨论停点、超载边界或版本末尾且绝不重复启播；成功的
手动控制取消待生效预约，主持权交接保留预约；无权、过期修订号、非未来时刻、播放中预约或不安全
起点均明确拒绝且房间不变。

技术栈：Node.js + Express + SQLite（better-sqlite3），原生 HTML/CSS/JS 前端，无前端构建步骤。

## 灯光规则

- 亮度范围 **0～100**，按**线性渐变**变化。
- 每条 Cue 在指定时码（非负秒数，支持小数）触发，把目标灯具从触发瞬间的**实际亮度**
  渐变到目标亮度；渐变时长为非负秒数，`0` 表示瞬变。
- **中途接管**：新 Cue 到来时，若同一盏灯仍在渐变中，效果从该时刻的实际亮度直接转向
  新目标（不跳变、不重置）。
- **同秒顺序**：同一秒触发的多条 Cue，按 Cue 编号（正整数、唯一）从小到大依次生效。
- **不可变版本**：发布即对当前灯具与草稿 Cue 做完整快照。开始播放后始终使用开始时所选的
  版本；之后继续编辑草稿或发布新版本，都不会影响正在/已开始的那次播放。
- 提交校验：非法时码（负数/非数字）、未知灯具编号、无效亮度（超出 0～100/非数字）
  或非法渐变时长会明确指出错误，并且**整次提交被拒绝**（批量录入任意一行非法则全部不落库）。

## 临时调光记录（覆盖 / 归还）

排演人员可针对**已发布版本**建立独立的临时调光记录（不改动任何版本与草稿）：

- **绑定快照**：记录建立时绑定该版本完整快照；原版 Cue 仍按既有规则（线性渐变、同秒顺序、
  中途接管）在后台运行。之后修改草稿或发布新版本**都不改变既有记录**。
- **覆盖（override）**：从操作瞬间的**实际输出**线性渐变到 0～100 的目标亮度，此后保持，
  直到被后续操作接管；时长 0 秒立即生效。
- **归还（return）**：以操作瞬间的**实际输出**为起点，在指定时长内按进度（0→1）
  与该时刻**持续变化的原版亮度**线性融合，结束后完全跟随原版；时长 0 秒立即生效。
- **接管与同秒**：下一操作可接管未完成的渐变（起点取接管瞬间实际输出，不跳变）；
  同一时码的多条操作按**追加顺序**依次生效。
- **操作字段**：灯具、非负时码、类型（`override`/`return`）、非负时长；覆盖另需目标亮度 0～100。
- **只准追加**：时码不得早于末项操作（同秒可继续追加）。
- **修订号（乐观并发）**：每次成功追加后记录修订号 +1，提交必须携带当前修订号；
  过期修订号返回 **409 冲突且不写入**，刷新后可用最新序列重试。
- **原子提交**：无效参数、未知灯具（不在绑定快照中）、时码回退、记录不存在等都明确报错，
  整次提交（含批量）**不部分写入**。
- **随时重算**：跳转或刷新页面后，依据绑定的版本快照与操作序列重算任意时刻逐灯实际输出
  （页面地址栏 `#record=<id>&t=<时刻>` 可直接定位到某记录的某时刻）。

## 回路负载预判（超载区间）

排演时还可预判灯光回路是否超载：

- **草稿配置**：在灯具页建立回路并设置**正数容量（瓦）**；为每盏灯选择所属回路并登记
  **正数额定瓦数**。**未分配回路**的灯具不计入任何回路负载。
- **随发布冻结**：发布版本时连同灯具、Cue 一起把回路与接线（灯具→回路、额定瓦数）
  写入不可变快照；之后再改草稿回路配置不影响已发布版本，也不影响绑定该版本的调光记录。
  早于本功能发布、快照内没有回路配置的旧版本仍可正常播放，负载分析返回空回路（不产生负载）。
- **分析目标**：选择一个**已发布版本**，或**绑定它的临时调光记录**（后者按覆盖/归还后的
  实际输出计算）。给定**非负时窗** `[start,end]` 与窗内查看时刻 `at`。
- **负载口径**：每盏灯 `实际亮度 ÷ 100 × 额定瓦数`，按所属回路汇总（实际亮度遵循线性渐变、
  同秒顺序、瞬变、中途接管，以及归还时与持续变化的原版亮度融合等既有规则）。
- **返回内容**：查看时刻各回路的负载/余量/是否超载，与时窗内负载**严格大于**容量的
  **全部连续区间**及端点包含性（`[ ]` 含端点、`( )` 不含端点；零长度时窗只返回该时刻负载）。
- **精确解析，不做固定步长采样**：相邻转折点（Cue 触发/渐变结束、覆盖/归还操作的触发与结束）
  之间，每灯实际亮度至多为一次式；归还融合段为“线性进度 × 原版线性亮度”，回路负载呈
  **二次形**，系统用一次/二次方程精确求根，因此夹在转折点之间的极短超载也不会漏。
- **只读**：分析不修改草稿、版本、调光记录，也不影响播放；既有亮度接口语义保持不变。
- **明确拒绝**：非正数容量、非正数额定瓦数、引用不存在的回路、负数/非数字时窗、起点大于终点、
  查看时刻越界、分析目标缺失或同时给出版本与记录等，均返回 `400/404` 中文错误且**不部分保存**。

## 草稿三方合并（把另一已发布版本合入当前草稿）

两组排演人员从**同一已发布版本**分别改稿后，可把另一组发布的版本合入当前草稿：

- **输入**：`base_version_id`（两组共同的基线版本）与 `incoming_version_id`（另一组发布的
  待合入版本）；当前草稿（draft）为其中一方的成果。
- **比较维度**：按**灯具/回路编号、Cue 编号、灯具接线**（灯具→回路、额定瓦数）做三方比较。
- **自动合入**：仅一侧改动（待合入侧的新增/修改/删除，草稿侧未动）、或两侧改成相同内容。
  草稿侧自身的改动保持现状。
- **列为冲突**（页面可逐项选择**保留草稿**或**采用待合入版本**）：
  - 两侧相对基线做了**不同修改**；
  - **删除与修改并存**（一侧删除、另一侧改名/改值）；
  - **同编号新增异值**（两侧都新增了同一编号但内容不同）；
  - **名称重名**（灯具名称、回路名称唯一；会在会导致重名的那一侧标注警示）；
  - **Cue 引用缺失**（Cue 引用的灯具在合并结果中不存在）；
  - **接线引用缺失**（接线指向的回路在合并结果中不存在）；
  - Cue/接线所依赖的灯具/回路在另一侧被删除时，被引用实体作为**联动冲突**一并列出，
    需与引用方选择同一侧；随冲突灯具新增的接线等**附着项**自动跟随主体同侧。
- **预览不写库**：`POST /api/merge/preview` 只读比较并返回自动改动、冲突两侧值与一次性
  预览令牌（`token`）。
- **提交规则**：`POST /api/merge/commit` 携带令牌与逐项 `resolutions`。
  - 草稿在预览之后被编辑过（灯具/回路/接线/Cue 任一变化）→ **409**，令牌作废，须重新预览；
  - 仍有冲突未选择、抉择值非法、或最终结果仍违反唯一性/引用规则 → **400 整次拒绝**，不写入；
  - 通过后以**一次事务**重写灯具、回路、接线和 Cue，返回合并后的新草稿；
  - **已发布版本及绑定它们的调光记录不变**（快照不可变）。
- 预览令牌有效期 24 小时，成功提交后立即失效（一次性）。

调用示例见下文「草稿合并 HTTP API」。

## 共享房间（同一舞台同步观看）

排演人员可基于一个**已发布版本**创建**共享房间**，多人同步观看同一舞台与逐灯亮度：

- **创建者持密钥，其他人凭房间码**：创建返回 6 位房间码与一次性**控制密钥**（请妥善保存，
  此后任何接口都不再回显）；凭房间码即可加入观看，控制操作必须携带正确密钥。
- **房间固定所选版本**：创建时绑定该版本的不可变快照，页面里的舞台/亮度/Cue 与播放器走
  同一套渐变引擎（线性渐变、同秒编号顺序、瞬变、中途接管）。之后修改草稿或发布新版本
  **都不影响**已创建的房间。
- **服务端按时钟推算**：房间保存播放/暂停状态、**基准时码 + 基准墙钟**、速度与**修订号**。
  当前时码 = 基准时码 +（服务端当前墙钟 − 基准墙钟）× 速度；播放到版本末尾**自动停住**
  （惰性落库，不产生修订号变化）。
- **刷新 / 重启 / 重连均可恢复**：状态全部持久化在 SQLite；页面刷新、服务重启、观看者
  重连后凭房间码即可恢复进度（播放中按绝对墙钟继续推算，暂停则停在固化时码）。
- **持密钥者可控制**：播放 `play`、暂停 `pause`、跳转 `seek`、设置速度 `speed`
  （**仅 0.5 / 1 / 2** 三档，与播放器一致）。每次成功控制修订号 +1；控制请求必须携带
  **当前修订号**，过期返回 **409 冲突且不改房间**，客户端按响应校时后重试。
  停在末尾再按播放会从头开始；跳到末尾立即停住。
- **观看端按服务端校时**：房间状态响应带 `server_wall`（服务端墙钟）与 `server_time`
  （该墙钟对应的时码），前端以此为锚点本地推算、每秒轮询纠正；观看者只读，控件自动禁用。
- **回路超载保护（创建时可选启用）**：
  - 创建房间时勾选启用，或在创建请求中带 `"overload_protection": true`；未启用的房间
    **完全沿用原行为**。是否启用在创建时固定，之后不可更改（可另建房间）。
  - 保护**只使用房间固定版本快照**中的回路容量与灯具接线（与负载预判同一份冻结数据）；
    旧版无回路配置时 `configured=false`，没有任何超载回路，播放照常。
  - 服务端按既有逐灯亮度与负载规则（线性渐变、同秒顺序、瞬变、中途接管，精确一/二次求根，
    不做步长采样），预先算好各回路严格超载区间；播放惰性推算时找出**播放方向上首个**
    超载区间左边界，播放抵达该边界即**自动暂停在此**，并惰性落库——**不因观看端轮询间隔
    长而越过危险段**；响应返回触发回路与演出时码。
  - **当前时码已超载**（暂停停在超载段中）时按播放会被**拒绝（400）**；**播放中跳入超载段**
    同样拒绝且**房间不变**；**暂停时允许任意跳转**（用于跳过/避开危险段），跳转后可重新播放。
  - 倍速改变以**实时推算时码**为新基准继续；服务**重启后按墙钟与冻结版本恢复**保护状态
    （触发信息持久化）；自动暂停**不增加控制修订号**，与“到末尾自动停住”一致。
  - 房间状态的 `protection` 字段持续报告：`enabled` / `configured`、当前是否超载
    （`overloaded_now` 及回路列表）、前方最近触发边界 `next_trip`、以及已触发时的
    `tripped`（触发原因中文说明、时码、回路）。页面据此显示保护状态与触发原因。
- **明确报错**：无效/不存在的版本、房间码（格式错误 400 / 不存在 404）、缺少或错误的
  密钥（403）、非法时码（负数/非数字/超过版本末尾）、非法速度、过期修订号（409）、
  保护开关非布尔值（400）、当前/目标时码已超载（400，附 `reason/time/circuits`）都返回
  中文错误且不改动房间。
- **只读副作用**：房间操作不改动版本、草稿、调光记录；既有接口语义全部保持不变。

### 主持权交接（一次性五分钟凭证）

当前主持人可把主持权安全移交给另一位排演人员，播放/暂停状态、时码、速度、固定版本与
超载保护状态都**不因交接而重置**：

- **主持人发起交接**：凭**当前控制密钥**与**房间当前修订号**调用发起接口，取得一份
  **仅显示一次、五分钟有效**的交接凭证（48 位十六进制）。发起交接本身**不增加修订号**。
- **同一房间同时只保留一份待领取凭证**：再次发起即覆盖旧凭证，旧凭证立刻失效。
- **接班人领取**：凭**房间码 + 交接凭证**（并携带看到的房间修订号）领取**新的控制密钥**。
  领取与房间修订号 +1 在服务端**同一事务内原子完成**，**旧密钥即刻失效**；**并发领取至多
  一人成功**，其余得到明确拒绝，**重试不会回显新密钥**（新密钥仅在领取成功的那次响应中
  返回一次）。
- **原主持人再控制即作废**：凭证发出后，若原主持人又**成功控制了房间**（修订号前进），
  凭证即作废，接班人领取得到 **409** 明确提示，须让主持人**重新索取**凭证。
- **明确拒绝、控制权不变**：**过期凭证**（超过五分钟）→ **403**；**错误/缺失凭证** → **403**；
  **过期修订号**（客户端修订号落后、或凭证绑定修订号已被主持人后续控制推进）→ **409**。
  所有拒绝都不改变控制权、不重置播放状态。
- **观看者仍只读**：房间状态接口始终只报告交接**状态**（是否有待领取凭证、剩余秒数、
  到期墙钟、作废/过期原因），**不向任何人回显凭证本体或控制密钥**；页面显示当前交接状态，
  主持人侧有「发起交接/凭证一次显示」区，观看者侧有「粘贴凭证领取」区。

调用示例见下文「主持权交接 HTTP API」。

## 共享房间循环排演（1～8 段循环）

当前主持人可在房间的**固定演出版本**上编排一次循环排演，用于反复打磨某几段演出：

- **编排段**：一次提交 **1～8 段**，按数组顺序依次播放。每段给出：
  - `start` / `end`：**非负**起止演出时码（秒，可小数），**起点须严格早于终点**，
    且**终点不超过版本末尾**；
  - `repeat`：该段的**正整数**重复次数（可以非常大，服务端按代数精确推算，不逐轮循环）。
- **提交与修订号**：提交携带当前**控制密钥**与**房间修订号**；过期修订号、无效段、
  无权操作（观看者/密钥错误）都明确报错且**不改变房间**。提交成功后**从首段开始播放**、
  房间修订号 **+1**，并与成功控制同一口径使**已发出的交接凭证作废**。
- **播放语义**：播放完全由服务端按**墙钟 + 当前倍速**（0.5/1/2）驱动，依次穿过各段；
  到达段尾的瞬间**立即跳回本段起点**（本段还有轮次）或**跳到下段起点**（本段轮次已尽），
  跳跃不消耗墙钟时间，因此跳跃落点之间未连续经过的演出时间不会播放到。
  **全部段全部轮次完成后停在末段终点**（`finished`，惰性落库、不增加修订号）；
  此时再按播放会**从首段重新开始**整次编排。
- **查询进度**：房间状态的 `program` 字段返回段列表、**当前段、当前轮次、时码与状态**
  （`playing` / `paused` / `finished`）；观看者同样可见进度（只读），但**看不到密钥**。
  页面刷新、观看者重连、服务重启后进度一致（段/轮/时码全部持久化在 SQLite）。
- **暂停与改速保留进度**：暂停把当前段/轮/段内时码固化为新基准；改速以实时推算时码为
  新基准继续；继续播放**从断点接续**，不重置段与轮次。
- **手动跳转取消编排**：`seek`（含页面上的「跳转」「回到起点」）会**删除编排**并沿用
  原房间控制语义（播放/暂停状态与时码处理同普通房间）；也可调用专门的取消接口。
- **回路超载保护联动**（仅创建时启用保护的房间）：
  - 提交时若**某段起点本身已处于严格超载区间**（含闭端点），**整次编排被拒绝（400）**，
    返回段序号、时码与超载回路，**不落库、不改房间、不加修订号**；
  - 运行途中抵达超载区间左边界仍按**现有规则自动暂停**在边界上（惰性落库、不加修订号），
    **不越过危险段**；段尾瞬时跳回/跳段不经过的时间不会触发拦截；
  - 暂停在边界后可**手动跳转避险**（同时取消编排），再重新播放或重新编排。
- **主持权交接**：编排不随交接重置——新主持人领取密钥后可继续播放/暂停/改速/取消/
  重新编排，段、轮次、时码、倍速与保护状态全部延续；观看者始终只读。
- **兼容**：未编排房间（含创建后从未编排、手动跳转/取消之后）**完全保持原行为**，
  房间状态不带 `program` 字段；既有房间接口语义不变。

调用示例见下文「循环排演 HTTP API」。

## 共享房间讨论停点（预置时码，经过即自动暂停）

排演人员可在共享房间预置一组**讨论停点**，播放到点即自动暂停，方便就某个时刻逐灯讨论：

- **预置与整组替换**：主持人凭**当前控制密钥**与**房间修订号**提交一组**不重复的非负
  演出时码**（秒，可小数，**不超过房间固定版本末尾**），整组校验后**原子替换**旧组；
  提交**空组表示清除**全部停点。无权（缺/错密钥 → 403）、过期修订号（409）或任一非法
  时码（400）都**不改变房间**；成功替换修订号 **+1**（与成功控制同一口径，已发出的
  交接凭证随之作废）。
- **触发**：播放按**服务端墙钟连续经过**下一停点时**准确暂停在该停点**，响应与页面
  显示触发原因（`stops.tripped`）；自动暂停**不增加修订号**（惰性落库），页面刷新、
  服务重启、观看者重连后停点与触发状态一致。
- **继续播放越过刚触发的停点**：停在停点上再按播放会直接越过它（锚点上的停点不再
  触发），到下一停点再次暂停。**循环排演每次重新经过仍须暂停**（每轮穿过段内停点
  都会再次停住）；**段尾瞬时跳转不触发被跳过的停点**（段间空隙与跳转落点上的停点
  都不触发）。
- **手动跳转**：`seek` 沿用取消编排规则；**跳到停点不立即触发**（落点成为新锚点，
  从该处播放会越过这个停点）。
- **与超载边界的关系**：播放方向上**先抵达者**生效；停点与超载边界**同一时码时
  超载优先**（返回 `protection.tripped` 而非停点触发）。
- **观看者只读**：房间状态的 `stops` 块始终可见（预置列表、下一停点预告、触发原因），
  但维护停点仅持密钥者可用；任何响应都**不含控制密钥**。
- **主持权交接**：停点不随交接重置，新主持人领取密钥后可继续维护停点。

调用示例见下文「讨论停点 HTTP API」。

## 共享房间定时启播（预约未来墙钟时刻，到点自动播放）

主持人可为**暂停中的共享房间**预约一个未来墙钟时刻，到点自动从当时断点播放，适用于
「休息到 19:30 自动接着排」一类场景：

- **预约与覆盖**：主持人凭**当前控制密钥**与**房间修订号**提交启播时刻 `start_at`
  （**Unix 秒数**或 **ISO 8601** 日期时间，如 `1759305600` 或 `"2026-10-03T19:30:00"`），
  时刻必须**严格晚于当前墙钟**。同一房间同时**只保留最近一次预约**（再次预约直接覆盖旧预约）；
  预约期间房间保持**暂停**（时码、速度都不动）。无权（缺/错密钥 → 403）、过期修订号（409）、
  时刻缺失/非法/非未来（400）都**不改变房间**；预约成功修订号 **+1**。
- **取消**：专门的取消接口删除待生效预约，修订号 **+1**；没有待生效预约时返回 400 且
  房间不变。**任何成功的手动控制**（播放/暂停/跳转/改速、循环排演提交/取消、讨论停点维护）
  都会取消待生效预约；**主持权交接保留预约**（新主持人可改可取消）。
- **到点启播规则**：到点按**现有播放规则**从**当时断点**启动——普通房间停在末尾则从头开始，
  进行中的循环排演从断点接续，**已完成（finished）的循环排演从首段重来**。启用超载保护时，
  若预约启播的起点已处于超载区间（**不安全起点**），预约在提交时即被 400 拒绝且房间不变；
  0 时长（无 Cue）版本同样拒绝预约。
- **绝对墙钟与重启恢复**：启播锚点是预约的**绝对墙钟时刻**。服务在到点后重启、或到点时无人
  查询、首次查询已晚于预约时刻时，仍**以预约时刻起算**墙钟进度，由现有惰性推算准确停在
  **先遇到的讨论停点、超载区间左边界或版本末尾**（轮询间隔再长也不会越过）。启播与删除预约
  在**同一事务**完成，因此**绝不会重复启播**。
- **修订号语义**：预约与取消各使修订号 **+1**；**自动启播本身不增加修订号**（与到末尾停住、
  超载/停点自动暂停同一口径）。启播结果由房间状态的 `playing`、`stops.tripped`、
  `protection.tripped` 与 `schedule` 块共同呈现。
- **观看者只读**：房间状态的 `schedule` 块始终可见（待生效预约 / 已启播标记），但预约与
  取消仅持密钥者可用；任何响应都**不含控制密钥**。

调用示例见下文「定时启播 HTTP API」。

## 一键启动（Docker Compose）

需要 Docker 与 Docker Compose 插件。在本目录执行：

```bash
docker compose up --build -d
```

该命令会一次性完成：安装依赖 → 初始化 SQLite 数据库与表结构 → 启动服务。

启动后访问：

- 地址：<http://localhost:3000>
- 端口：容器内固定 `3000`，宿主机默认映射到 `3000`（可用 `HOST_PORT` 修改）

停止：

```bash
docker compose down          # 停止（数据保留在命名卷 cue-data 中）
docker compose down -v       # 停止并删除演出数据
```

查看日志：`docker compose logs -f`

## 配置（环境变量）

在 docker-compose.yml 中配置，或通过 `.env` / 环境变量覆盖：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `HOST_PORT` | `3000` | 宿主机映射端口（访问端口），如 `HOST_PORT=8080 docker compose up -d` |
| `PORT` | `3000` | 容器内监听端口（改动需同步调整 compose 的端口映射） |
| `DB_PATH` | `/data/app.db` | SQLite 数据库文件路径；位于挂载卷中，容器重建不丢数据 |
| `NODE_ENV` | `production` | 运行环境 |

## 使用说明

1. **灯具录入**：添加灯具（名称唯一），系统自动分配灯具编号 `#1、#2 …`。
   - 在同页「灯光回路」中建立回路（名称唯一、正数容量），并在灯具表内为每盏灯选择所属回路、
     填写正数额定瓦数；选「未分配」即不计入任何回路负载。容量/瓦数/回路引用非法会被拒绝。
2. **草稿 Cue**：
   - 单条录入：选择灯具、填写触发秒数、目标亮度（0～100）、渐变秒数；
     Cue 编号可留空自动分配，也可手填正整数。
   - 批量录入：每行 `时码 灯具编号 目标亮度 渐变时长 [Cue编号]`，空格分隔；
     任一行非法将拒绝整次提交。
   - 草稿可随时编辑/删除；这些改动只作用于草稿。
3. **发布版本**：填写备注（可留空）后点击“冻结并发布当前草稿”，生成不可变版本。
4. **排演播放**：选择版本后即可 ▶ 播放 / ⏸ 暂停 / ⏹ 回起点 / 拖动时间轴 / 输入秒数跳转，
   可切换 0.5× / 1× / 2× 速度；舞台模拟、亮度条与 Cue 状态（等待 / 渐变中 / 已触发）
   随时间实时更新。快捷键：页面空白处按空格播放/暂停。
5. **版本比对**：选择两个已发布版本（允许相同），输入非负时窗起点/终点、时窗内的查看时刻
   与 0～100 的亮度差阈值，页面显示该时刻两版逐灯亮度，并精确列出时窗内各灯亮度差
   **严格大于**阈值的连续区间及端点包含性（`[ ]` 含端点、`( )` 不含端点，零长度 `[t,t]`
   表示仅该瞬间超差）。按灯具编号匹配；仅在一版存在的灯具单列为**配置差异**，缺失不当作熄灭；
   无差异返回空区间；零长度时窗只返回该时刻亮度。区间在转折点（Cue 触发时刻、渐变结束时刻）
   之间用一次方程求阈值交点，**不做固定间隔采样**，同秒编号顺序、瞬变、中途接管、线性渐变
   规则与播放器完全一致。比对只读发布快照，不修改草稿，也不影响任何播放会话。
6. **临时调光记录**：在「调光记录」页选择已发布版本并建立记录，打开后选择灯具、填写演出时码、
   类型（覆盖/归还）、时长（覆盖再填目标亮度）追加操作；拖动时间轴或输入查看时刻即可重算
   逐灯的原版亮度与实际输出（覆盖中/归还融合中/跟随原版）。操作只追加（时码不早于末项，
   同秒按追加顺序）；若有人同时追加导致修订号过期，会自动拉取最新序列后提示重试。
7. **回路负载**：在「回路负载」页选择已发布版本或某条调光记录，输入非负时窗与窗内查看时刻，
   页面显示该时刻各回路容量/负载/余量与超载标记，并精确列出时窗内严格超出容量的连续区间
   （`[ ]`/`( )` 标明端点是否包含）。分析只读，草稿与回路配置的后续改动不影响已冻结版本。
8. **版本合并**：在「版本合并」页选择共同基线版本与另一组发布的待合入版本，点击三方比较预览：
   页面分区列出**可自动合入的单侧改动**与**冲突**；每条冲突用单选选择「保留草稿」或
   「采用待合入版本」（会导致重名或引用缺失的一侧有红色警示；联动冲突需与引用方同侧）。
   提交后以一次事务更新草稿；若预览后草稿被改过会提示重新预览。已发布版本与调光记录不变。
9. **共享房间**：在「共享房间」页选择已发布版本，可勾选「启用回路超载保护」后创建房间，
   页面显示**房间码**与**控制密钥**
   （密钥仅显示一次并保存在本浏览器；把房间码发给其他排演人员）。其他人输入房间码即可加入，
   观看同一舞台、逐灯亮度与 Cue 状态；页面按服务端墙钟校时并每秒同步。持密钥者可播放/暂停/
   跳转/切换 0.5×、1×、2×；若多人控制导致修订号过期，会自动按服务端状态校时后提示重试。
   **主持权交接**：持密钥者在房间控制条下方的「主持权交接」区点击发起，页面生成一份
   **五分钟有效、仅显示一次**的交接凭证（同房间再次发起会让旧凭证立即失效）；接班人以
   观看者身份加入同一房间，把凭证粘贴到交接区「领取新控制密钥」，领取成功即成为新主持人，
   旧密钥立刻失效（原持密钥浏览器下次控制时自动降级为观看者）；播放状态、时码、速度、
   固定版本与超载保护状态都不重置。凭证发出后主持人若又控制了房间，凭证即作废，页面会
   提示接班人重新索取；观看者只能看到「交接进行中/已过期/已作废」状态，看不到凭证或密钥。
   启用保护的房间在控制条上方显示**保护状态条**：前方首个超载边界、当前已超载（禁止播放）
   或已在边界自动暂停的触发回路与演出时码；播放抵达超载区间左边界会自动暂停且不越过，
   暂停时可跳转避险。刷新页面（地址栏 `#room=<房间码>` 会自动重连）或服务重启后进度与保护
   状态都在；之后改草稿、发新版不影响该房间，房间操作也不会改动版本、草稿或调光记录。
   **循环排演**：持密钥者在房间页「循环排演」卡逐段填写起点/终点（非负、起点早于终点、
   不超过版本末尾）与正整数重复次数（最多 8 段，可增删行），点击「提交并从首段开始」即按
   当前倍速依次循环播放：段尾自动跳回本段起点或下段起点，状态条实时显示当前段/轮次/时码，
   全部走完停在末段终点（再按播放从头重演）。暂停、改速都保留段/轮进度并从断点接续；
   手动「跳转」或「回到起点」会提示并取消编排回到普通房间，也可用「取消当前编排」按钮。
   启用超载保护的房间，超载的段起点会直接拒绝整次编排（页面显示原因），播放途中遇到超载
   边界仍自动暂停、不越过危险段。主持权交给接班人后，新主持人可继续控制同一段循环排演；
   观看者只读查看当前段/轮次/时码，看不到编排之外的任何密钥。
   **讨论停点**：持密钥者在房间页「讨论停点」卡输入一组时码（逗号/空格分隔，留空提交即清除），
   点击「保存停点（整组替换）」预置；播放连续经过下一停点即自动暂停并显示原因（控制条上方
   状态条与停点卡同步显示触发时码），按播放继续即越过该停点；观看者只读查看停点列表、
   下一停点预告与触发原因。
   **定时启播**：持密钥者先把房间**暂停**，在房间页「定时启播」卡选择一个未来的本机日期时间，
   点击「⏰ 预约定时启播」即可（同一房间只保留最近一次预约，可用「取消预约」撤销；输入框默认
   预填五分钟后，直接改到需要的时刻即可）。控制条上方状态条显示启播墙钟与倒计时；到点房间
   自动从断点播放——进行中的循环排演断点接续、已走完的编排从首段重来，普通房间停在末尾则从头
   开始，途中仍准确停在先遇到的讨论停点、超载边界或版本末尾。到点时即使页面没人开着、或服务
   刚重启，也按预约的绝对时刻补算进度，不会重复启播；任何成功的播放/暂停/跳转/改速、循环排演
   或停点操作都会取消待生效预约，主持权交接后预约保留、由新主持人接管。观看者同样能在状态条
   看到「已预约/已启播」，但看不到任何密钥。

## 回路负载 HTTP API

`GET /api/load`（query 参数）或 `POST /api/load`（JSON body），参数相同。
分析目标二选一：

| 参数 | 含义 |
| --- | --- |
| `version_id` | 已发布版本编号（与 `record_id` 二选一；不存在返回 404） |
| `record_id` | 绑定某版本的临时调光记录编号（按覆盖/归还后的实际输出计算） |
| `start` / `end` | 非负时窗起止秒数，`start > end` 报错；相等为零长度时窗 |
| `at` | 查看时刻（非负秒数），必须落在 `[start,end]` 内 |

负载 = 该时刻各成员灯 `实际亮度/100×额定瓦数` 之和；`intervals` 为负载**严格大于**容量的
全部连续区间。转折点之间按一次/二次方程精确求根（归还融合产生二次形），不做固定步长采样。

调用示例：

```bash
# 分析版本 1 在时窗 [0,60] 内、查看时刻 t=12s 的回路负载
curl 'http://localhost:3000/api/load?version_id=1&start=0&end=60&at=12'

curl -X POST http://localhost:3000/api/load \
  -H 'Content-Type: application/json' \
  -d '{"version_id":1,"start":0,"end":60,"at":12}'

# 分析绑定该版本的调光记录 2（含临时覆盖/归还的实际输出）
curl -X POST http://localhost:3000/api/load \
  -H 'Content-Type: application/json' \
  -d '{"record_id":2,"start":0,"end":60,"at":12}'
```

返回（节选）：

```json
{
  "source": {"kind": "version", "version": {"id": 1, "label": "首演"}},
  "window": {"start": 0, "end": 60},
  "at": 12,
  "has_circuit_config": true,
  "circuits": [
    {
      "circuit_id": 1,
      "name": "面光回路",
      "capacity": 1500,
      "lights": [
        {"light_id": 1, "name": "面光1", "watts": 300}
      ],
      "load_at": 960,
      "overloaded": false,
      "intervals": [
        {"start": 30, "end": 45, "start_inclusive": false, "end_inclusive": true}
      ]
    }
  ]
}
```

- `has_circuit_config` 为 `false` 表示该版本发布时没有回路配置（早期版本）：`circuits` 为空，
  播放照常、不产生回路负载。
- `intervals` 只含超载区间；与容量恰好相等的时刻不算超载（交点端点开区间）；
  Cue/操作触发瞬间若超载则该端点为闭端点；零长度时窗 `intervals` 恒为 `[]`。
- 未分配回路的灯具不出现在任何回路的 `lights` 中，不计入负载。
- 版本/记录不存在 → 404；时窗非法、查看时刻越界、目标缺失或同时给出版本与记录 → 400。
  分析只读，不改变草稿、版本、记录或播放。

## 版本比对 HTTP API

`GET /api/compare`（query 参数，便于直接调用/分享）或 `POST /api/compare`（JSON body），
参数相同：

| 参数 | 含义 |
| --- | --- |
| `version_a` / `version_b` | 两个已发布版本编号（正整数；允许相同；任一不存在返回 404） |
| `start` / `end` | 非负时窗起止秒数，`start > end` 报错；二者相等为零长度时窗 |
| `at` | 查看时刻（非负秒数），必须落在 `[start, end]` 内 |
| `threshold` | 亮度差阈值，0～100（含边界）；严格大于才算超差 |

调用示例：

```bash
curl 'http://localhost:3000/api/compare?version_a=1&version_b=2&start=0&end=10&at=4&threshold=30'

curl -X POST http://localhost:3000/api/compare \
  -H 'Content-Type: application/json' \
  -d '{"version_a":1,"version_b":2,"start":0,"end":10,"at":4,"threshold":30}'
```

返回（节选）：

```json
{
  "versions": {"a": {"id": 1, "label": "首演"}, "b": {"id": 2, "label": "复排"}},
  "window": {"start": 0, "end": 10},
  "at": 4,
  "threshold": 30,
  "levels": [
    {"light_id": 1, "name": "面光1", "brightness_a": 40, "brightness_b": 20,
     "difference": 20, "exceeds": false}
  ],
  "intervals": [
    {"light_id": 2, "name": "侧光L", "intervals": [
      {"start": 5, "end": 7.5, "start_inclusive": true, "end_inclusive": false}
    ]}

  "config_differences": {
    "only_in_a": [{"light_id": 3, "name": "逆光"}],
    "only_in_b": []
  }
}
```

- `intervals` 只含有差异的灯具；无差异时为 `[]`。`start_inclusive/end_inclusive`
  标明区间端点是否包含（阈值交点不含；Cue 触发瞬间若超差则含）。
- 起点大于终点、查看时刻越界、非数字/负数参数、阈值越界（<0 或 >100）、
  版本不存在等情况均返回 `400/404` 与中文错误原因。

## 临时调光记录 HTTP API

记录（record）绑定一个已发布版本；操作（op）只能追加。修订号用于乐观并发控制。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/records` | 建立记录 `{version_id, label?}`，返回记录详情（含绑定快照与空操作序列） |
| GET | `/api/records` | 记录列表（含修订号、操作数、绑定版本） |
| GET | `/api/records/:id` | 记录详情：元数据 + 绑定版本的灯具/Cue 快照 + 操作序列（刷新/跳转后据此重算） |
| DELETE | `/api/records/:id` | 删除记录及其全部操作 |
| POST | `/api/records/:id/ops` | 追加操作：单条 `{revision, op}` 或批量 `{revision, ops:[...]}`，整批事务 |
| GET | `/api/records/:id/output?at=<时码>` | 查看某时刻逐灯原版亮度与实际输出（只读重算） |

操作对象字段：

| 字段 | 含义 |
| --- | --- |
| `light_id` | 灯具编号，必须存在于**绑定版本快照**中 |
| `time` | 非负演出时码（秒，可小数），不得早于当前末项操作的时码 |
| `op_type` | `override`（覆盖）或 `return`（归还） |
| `duration` | 非负时长（秒）；`0` 立即生效 |
| `target` | 仅覆盖需要：0～100 目标亮度；归还携带该字段会报错 |

调用示例：

```bash
# 1) 基于版本 1 建立记录
curl -X POST http://localhost:3000/api/records \
  -H 'Content-Type: application/json' \
  -d '{"version_id":1,"label":"技术联排夜场"}'

# 2) 在修订号 0 上追加一条覆盖：t=2s 把 #1 从当时实际输出渐变到 80，用时 6s
curl -X POST http://localhost:3000/api/records/1/ops \
  -H 'Content-Type: application/json' \
  -d '{"revision":0,"op":{"light_id":1,"time":2,"op_type":"override","target":80,"duration":6}}'

# 3) 同秒追加两条操作（按数组顺序生效）：#2 先瞬变到 10，再用 2s 归还到原版
curl -X POST http://localhost:3000/api/records/1/ops \
  -H 'Content-Type: application/json' \
  -d '{"revision":1,"ops":[
        {"light_id":2,"time":8,"op_type":"override","target":10,"duration":0},
        {"light_id":2,"time":8,"op_type":"return","duration":2}
      ]}'

# 4) 查看 t=9s 的逐灯实际输出（原版仍在后台运行）
curl 'http://localhost:3000/api/records/1/output?at=9'
```

追加成功返回最新记录详情（`revision` 已自增、`ops` 为完整序列）。冲突示例：

```json
{ "revision": 0, "op": {"light_id":1,"time":9,"op_type":"override","target":0,"duration":1} }
```

```json
{"error":"修订号冲突：提交基于修订号 0，记录当前已为修订号 2；请刷新操作序列后重试（本次未写入）"}
```

`GET /api/records/:id/output?at=9` 返回（节选）：

```json
{
  "record": {"id": 1, "label": "技术联排夜场", "revision": 2},
  "version": {"id": 1, "label": "首演"},
  "at": 9,
  "levels": [
    {"light_id": 1, "name": "面光1", "original": 90, "actual": 80, "overridden": true,
     "state": "override", "active_seq": 1},
    {"light_id": 2, "name": "侧光L", "original": 60, "actual": 60, "overridden": false,
     "state": "original", "active_seq": null}
  ]
}
```

- `state`：`override`（覆盖保持/渐变中）、`return`（归还融合中）、`original`（完全跟随原版）。
- 版本不存在 → 404；记录不存在 → 404；版本号/灯具/时码/时长/亮度/类型非法、
  时码早于末项、归还携带目标亮度、缺少修订号 → 400；修订号过期 → 409。
  批量追加时任一条非法则整批拒绝（**不部分写入**）。

请求体：

| 字段 | 含义 |
| --- | --- |
| `token` | 预览返回的一次性令牌 |

```bash
curl -X POST http://localhost:3000/api/merge/commit \
  -H 'Content-Type: application/json' \

```

```json
  "draft": {
    "lights": [ {"id": 1, "name": "面光A", "circuit_id": 1, "watts": 300} ],
    "circuits": [ {"id": 1, "name": "面光回路", "capacity": 2000} ],
```

- `400`：缺少/非法版本编号、`resolutions` 不是对象、引用了预览中不存在的 key、抉择值不是

## 共享房间 HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/rooms` | 基于已发布版本创建房间 `{version_id, label?, overload_protection?}`，返回房间状态与一次性 `control_key` |
| GET | `/api/rooms/:code` | 凭房间码查看房间状态（无需密钥；观看端据此校时），含 `protection` 保护状态与 `handover` 交接状态 |
| POST | `/api/rooms/:code/control` | 持密钥控制 `{control_key, revision, action, ...}`，成功返回最新房间状态；成功控制会使已发出的交接凭证作废 |
| POST | `/api/rooms/:code/handover/issue` | 当前主持人发起交接 `{control_key, revision}`，返回仅显示一次、五分钟有效的 `handover_token` |
| POST | `/api/rooms/:code/handover/claim` | 接班人领取新控制密钥 `{handover_token, revision}`，与修订号 +1 原子完成，返回仅显示一次的新 `control_key` |
| PUT | `/api/rooms/:code/schedule` | 预约定时启播 `{control_key, revision, start_at}`（Unix 秒或 ISO 8601，须为未来墙钟；仅暂停房间），同房间只保留最近一次预约，修订号 +1，返回最新房间状态（含 `schedule`） |
| POST | `/api/rooms/:code/schedule/cancel` | 取消待生效定时启播 `{control_key, revision}`，修订号 +1；无待生效预约时 400 且房间不变 |

房间码为 6 位大写字母数字（去除 `0/O/1/I` 等易混字符）；路径中可传小写或带连字符/空格，
服务端自动归一。

### 1) 创建房间

```bash
# 不启用回路超载保护（原行为）
curl -X POST http://localhost:3000/api/rooms \
  -H 'Content-Type: application/json' \
  -d '{"version_id":1,"label":"技术联排"}'

# 创建并启用回路超载保护（播放会在首个超载区间左边界自动暂停）
curl -X POST http://localhost:3000/api/rooms \
  -H 'Content-Type: application/json' \
  -d '{"version_id":1,"label":"技术联排（带超载保护）","overload_protection":true}'
```

返回（`control_key` **仅此次返回**）：

```json
{
  "code": "K7P2QX",
  "label": "技术联排（带超载保护）",
  "version": {"id": 1, "label": "首演"},
  "duration": 20,
  "playing": false,
  "time": 0,
  "speed": 1,
  "revision": 0,
  "protection": {
    "enabled": true,
    "configured": true,
    "overloaded_now": false,
    "circuits_overloaded_now": [],
    "next_trip": {
      "time": 12,
      "seconds_ahead": 12,
      "circuit": {"circuit_id": 1, "name": "面光回路", "capacity": 1500}
    }
  },
  "server_wall": 1759300000.123,
  "server_time": 0,
  "control_key": "d4e63d64…（48 位十六进制控制密钥，仅创建时返回一次）"
}
```

- `duration`：房间固定版本的末尾时刻（最后一条 Cue 渐变结束秒数），创建时一并冻结。
- `overload_protection`：可选布尔值（不传等同 `false`，沿用原行为）；非布尔值返回 400。
  是否启用创建时固定。启用后保护只读取该版本**冻结快照**中的回路容量与灯具接线。
- `protection` 字段（创建 / 查看 / 控制响应一致）：
  - 未启用：`{"enabled": false}`。
  - 已启用但固定版本无回路配置（旧版快照）：`{"enabled": true, "configured": false}`，
    没有超载回路，播放照常。
  - 已启用且有回路配置：另含 `overloaded_now`（当前时码是否处于严格超载区间，交点开端点
    不算超载）、`circuits_overloaded_now`（当前超载回路 `{circuit_id,name,capacity}` 列表）、
    `next_trip`（当前安全时，前方最近的触发边界 `{time, seconds_ahead, circuit}`；无则省略）、
    `tripped`（仅保护自动暂停后出现：`{reason:"overload_boundary", reason_text, time, circuit}`，
    服务重启后仍会恢复；普通控制/跳转离开后清除）。
- 版本编号非法 → 400；版本不存在 → 404。

### 2) 查看房间（加入 / 轮询校时）

```bash
curl http://localhost:3000/api/rooms/K7P2QX
```

返回当前状态（无 `control_key` 字段）。播放中时 `time` 由服务端按墙钟推算；若已到末尾，
本次请求会把房间**惰性落库为停在末尾**（修订号不变）。启用超载保护时，若推算已抵达前方
首个超载区间左边界，本次请求会把房间**惰性落库为暂停在该边界**（修订号同样不变），
`playing=false`、`time` 恰为边界时码，`protection.tripped` 给出触发回路与时码；
**无论距上次请求过了多久，返回时码都不会越过该危险段。**

- 校时方法：以响应的 `server_wall`（秒）/`server_time`（演出秒）为锚点，
  客户端时刻 `now` 对应的演出时码 = `server_time + max(0, now − server_wall) × speed`
  （暂停时恒为 `server_time`），到 `duration` 停住；启用保护时还应在 `next_trip.time`
  处停住（页面已内置）。
- 响应另含 `handover` 交接状态块（有待领取凭证时）：仅报告 `active`/到期墙钟/剩余秒数/
  `expired`、`superseded` 作废原因，**不含凭证本体或任何控制密钥**（详见下文
  「4.3 房间状态中的交接状态」）。
- 响应另含 `schedule` 定时启播块：待生效预约（启播墙钟/剩余秒数/断点）、已自动启播标记，
  或 `{"state":"none"}`；**若预约已到点（含服务重启后、或上次查询早于启播时刻），本次
  请求会先在同一事务内按预约的绝对墙钟惰性启播并推算到当前**——可能已在播放中，也可能已
  准确停在先遇到的讨论停点、超载边界或版本末尾（自动启播不增加修订号，且不会重复启播）。
- 房间码格式错误（不是 6 位）→ 400；房间不存在 → 404。

### 3) 控制房间（持密钥者）

请求体公共字段：`control_key`（控制密钥）、`revision`（客户端看到的当前修订号）、
`action`（`play` / `pause` / `seek` / `speed`）。

| action | 附加字段 | 语义 |
| --- | --- | --- |
| `play` | — | 从当前时码播放；已停在末尾则从头开始。**启用保护时：当前时码处于超载区间则 400 拒绝** |
| `pause` | — | 暂停并把推算出的当前时码固化为新基准 |
| `seek` | `time`（非负数字，≤ `duration`） | 跳转到指定时码；播放/暂停状态沿用，跳到末尾即停住。**启用保护时：播放中目标时码处于超载区间则 400 拒绝且房间不变；暂停时允许跳转（可避险）** |
| `speed` | `speed`（仅 `0.5` / `1` / `2`） | 以当前实时推算时码为新基准，立即按新速度走（保护若已截停则停在边界） |

```bash
# 播放（基于修订号 0）
curl -X POST http://localhost:3000/api/rooms/K7P2QX/control \
  -H 'Content-Type: application/json' \
  -d '{"control_key":"d4e63d64…","revision":0,"action":"play"}'

# 跳转到 12 秒（修订号已为 1）
curl -X POST http://localhost:3000/api/rooms/K7P2QX/control \
  -H 'Content-Type: application/json' \
  -d '{"control_key":"d4e63d64…","revision":1,"action":"seek","time":12}'

# 2 倍速
curl -X POST http://localhost:3000/api/rooms/K7P2QX/control \
  -H 'Content-Type: application/json' \
  -d '{"control_key":"d4e63d64…","revision":2,"action":"speed","speed":2}'
```

成功返回与「查看房间」相同的最新状态（`revision` 已 +1，`server_wall/server_time`
为本次控制后的新锚点）。

> 成功的控制会**取消该房间待生效的定时启播预约**并清除「已启播」标记（响应 `schedule`
> 回到 `{"state":"none"}`）；若预约恰在本次控制时已到点，服务端会先按预约墙钟完成一次
> 惰性自动启播（不增加修订号），再执行本次手动控制。主持权交接不取消预约。

启用超载保护时，播放期间无需额外动作：服务端在 GET/控制的实时推算中自动截停。
典型避险流程（暂停在超载边界 → 暂停态跳到安全时码 → 重新播放）：

```bash
# 播放后保护触发：GET 返回 playing=false、time=12、revision 不增加，protection.tripped 非空
curl http://localhost:3000/api/rooms/K7P2QX

# 暂停状态允许跳转避险（播放中跳入超载段会被拒绝）
curl -X POST http://localhost:3000/api/rooms/K7P2QX/control \
  -H 'Content-Type: application/json' \
  -d '{"control_key":"d4e63d64…","revision":3,"action":"seek","time":18}'

# 跳到安全段后再播放
curl -X POST http://localhost:3000/api/rooms/K7P2QX/control \
  -H 'Content-Type: application/json' \
  -d '{"control_key":"d4e63d64…","revision":4,"action":"play"}'
```

错误情形（均不改动房间）：

- `403`：缺少 `control_key`，或密钥错误（观看者无权控制）。
- `400`：缺少/非法 `revision`、未知 `action`、`seek` 的时码非数字/为负/超过版本末尾、
  `speed` 不是 0.5/1/2、创建房间时 `overload_protection` 不是布尔值；房间码格式错误。
  启用保护时，**当前时码已超载仍要求播放、或播放中要求跳入超载段**也返回 400
  （`reason: "overloaded_timecode"`，附 `time` 与超载的 `circuits`），且**不改动房间、
  不增加修订号**：

  ```json
  {
    "error": "时码 12 秒处 回路 #1「面光回路」 负载严格大于容量：当前已超载，拒绝播放；请先在暂停状态下跳转到安全时码（本次未改动房间）",
    "reason": "overloaded_timecode",
    "time": 12,
    "circuits": [{"circuit_id": 1, "name": "面光回路", "capacity": 1500}]
  }
  ```
- `404`：房间码不存在。
- `409`：修订号过期——

  ```json
  {"error":"修订号冲突：提交基于修订号 1，房间当前已为修订号 3；请按服务端最新状态校时后重试（本次未改动房间）"}
  ```

  客户端应重新 `GET` 房间状态、用新 `revision` 重试。注意：**保护自动暂停与到末尾停住都
  不增加修订号**，因此它们不会造成 409；只有成功的 `play/pause/seek/speed` 控制才 +1。

### 4) 主持权交接

主持权交接把控制密钥安全地换成一份新密钥，**播放/暂停、时码、速度、固定版本、超载保护
状态都不重置**；交接成功后房间修订号 +1（与领取原子完成），旧密钥即刻失效。

#### 4.1 发起交接（当前主持人）

`POST /api/rooms/:code/handover/issue`，请求体 `{control_key, revision}`：

- `control_key`：当前控制密钥（缺失/错误 → `403`）。
- `revision`：房间**当前修订号**（缺失/非法 → `400`；过期 → `409` 且不改动、不颁发凭证）。
- 成功返回与「查看房间」相同的房间状态，另附：
  - `handover_token`：48 位十六进制**一次性交接凭证**，**仅本次响应完整返回一次**，此后
    任何接口（含 GET 房间）都不再回显；
  - `handover_expires_in`：有效期秒数，固定 `300`（五分钟）。
- **同一房间同时只保留一份待领取凭证**：重复发起直接覆盖，旧凭证立即失效。
- 发起交接**不增加修订号**（凭证绑定发起时的修订号）。

```bash
# 主持人在修订号 2 时发起交接
curl -X POST http://localhost:3000/api/rooms/K7P2QX/handover/issue \
  -H 'Content-Type: application/json' \
  -d '{"control_key":"d4e63d64…（当前控制密钥）","revision":2}'
```

返回（节选）：

```json
{
  "code": "K7P2QX",
  "playing": true,
  "time": 6.4,
  "speed": 1,
  "revision": 2,
  "protection": { "enabled": false },
  "handover": {
    "active": true,
    "revision": 2,
    "issued_at": 1759300100.0,
    "expires_at": 1759300400.0,
    "seconds_remaining": 300
  },
  "server_wall": 1759300100.0,
  "server_time": 6.4,
  "handover_token": "7b1a9c…（48 位十六进制，仅显示这一次）",
  "handover_expires_in": 300
}
```

> 把**房间码**与 **handover_token** 一起交给接班人即可；主持人自己请保留响应截图之外的
> 安全渠道（接口不会再次提供该凭证）。

#### 4.2 领取新控制密钥（接班人）

`POST /api/rooms/:code/handover/claim`，请求体 `{handover_token, revision}`：

- `handover_token`：主持人给的一次性凭证（缺失 → `403`；错误/已使用/不存在 → `403`；
  已过期 → `403`）。
- `revision`：领取时看到的房间修订号（缺失/非法 → `400`；落后于房间当前值 → `409`，
  凭证保留，刷新修订号后可重试）。
- 若凭证发出后原主持人又成功控制过房间（凭证绑定修订号落后）→ `409` 凭证已作废，
  须重新索取。
- 成功在**同一事务内**换发新 `control_key`、房间修订号 +1、删除一次性凭证；响应即房间
  最新状态（播放/时码/速度/保护均延续），新密钥**仅本次返回一次**。

```bash
# 接班人凭房间码与凭证领取（此时房间修订号仍为 2）
curl -X POST http://localhost:3000/api/rooms/K7P2QX/handover/claim \
  -H 'Content-Type: application/json' \
  -d '{"handover_token":"7b1a9c…（主持人给的凭证）","revision":2}'
```

返回（节选；`control_key` 为**新**密钥，旧密钥立即失效）：

```json
{
  "code": "K7P2QX",
  "playing": true,
  "time": 9.8,
  "speed": 1,
  "revision": 3,
  "protection": { "enabled": false },
  "server_wall": 1759300103.4,
  "server_time": 9.8,
  "control_key": "a03f18…（新控制密钥，仅显示这一次）"
}
```

- 领取成功后没有 `handover` 字段（待领取凭证已删除）；立即用同一凭证重试只得到
  `403 {"error":"交接凭证无效…"}`，响应体**不含**新密钥。
- **并发领取至多一人成功**：多个接班人同时提交，仅一个 `200`，其余全部 `403`。
- 旧主持人此后再发控制请求得到 `403 控制密钥无效`（前端会自动降级为观看者）。

#### 4.3 房间状态中的交接状态（观看者也能看到，但无凭证/密钥）

`GET /api/rooms/:code`（以及创建/控制/交接的成功响应）中的 `handover` 字段：

- 不存在待领取凭证（含从未发起、已领取）：**不输出** `handover` 字段。
- 待领取中：

  ```json
  { "active": true, "revision": 2, "issued_at": 1759300100.0,
    "expires_at": 1759300400.0, "seconds_remaining": 287.4 }
  ```

- 已不可领取（不泄露凭证本体）：
  - `{"active": false, "revision": 2, "issued_at": …, "expires_at": …,
     "reason": "expired", "reason_text": "交接凭证已过期（有效期五分钟）…"}`；
  - `{"active": false, …, "reason": "superseded",
     "reason_text": "原主持人在凭证发出后又控制了房间，本交接凭证已作废…"}`。

错误情形一览（均不改变控制权、不重置播放状态）：

| 情形 | 状态码 | 说明 |
| --- | --- | --- |
| 发起：缺/错控制密钥 | 403 | 仅当前主持人可发起 |
| 发起：修订号缺失/非法 | 400 | 须为非负整数 |
| 发起：修订号过期 | 409 | 不颁发凭证、不改动房间 |
| 领取：缺凭证 | 403 | `缺少交接凭证…` |
| 领取：凭证错误/已被使用/已被新凭证取代 | 403 | `交接凭证无效…` |
| 领取：凭证已过期（>5 分钟） | 403 | `交接凭证已过期…`，凭证清除 |
| 领取：客户端修订号落后（凭证仍有效） | 409 | 凭证保留，GET 最新修订号后可重试 |
| 领取：凭证绑定修订号落后（主持人又控制过） | 409 | `交接凭证已作废…`，凭证清除，须重新索取 |
| 领取：修订号缺失/非法 | 400 | 不消耗凭证 |
| 房间码格式错误 / 不存在 | 400 / 404 | 与既有房间接口同一口径 |

## 循环排演 HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/rooms/:code/program` | 提交 1～8 段循环排演 `{control_key, revision, segments}`，成功后从首段开始播放、修订号 +1，返回最新房间状态（含 `program`） |
| POST | `/api/rooms/:code/program/clear` | 取消循环排演 `{control_key, revision}`：删除编排、沿用普通房间语义（播放状态与时码保留），修订号 +1 |

段对象字段：

| 字段 | 含义 |
| --- | --- |
| `start` | 非负起点时码（秒，可小数） |
| `end` | 终点时码：**`start < end`**，且 `end ≤ duration`（版本末尾） |
| `repeat` | 正整数重复次数（1～2^53 内的安全整数均可，服务端代数推算不逐轮循环） |

### 1) 提交循环排演

```bash
# 第 1 段 [2,8] 循环 3 次，第 2 段 [12,15] 走 1 次；成功后从 2 秒开始播放
curl -X POST http://localhost:3000/api/rooms/K7P2QX/program \
  -H 'Content-Type: application/json' \
  -d '{"control_key":"d4e63d64…","revision":0,
       "segments":[{"start":2,"end":8,"repeat":3},{"start":12,"end":15,"repeat":1}]}'
```

成功返回（节选）即最新房间状态，另含 `program` 块：

```json
{
  "code": "K7P2QX",
  "playing": true,
  "time": 2,
  "speed": 1,
  "revision": 1,
  "server_wall": 1759300200.0,
  "server_time": 2,
  "program": {
    "segments": [
      {"start": 2, "end": 8, "repeat": 3},
      {"start": 12, "end": 15, "repeat": 1}
    ],
    "segment_index": 1,      // 当前段（1 基）
    "segment_count": 2,
    "loop": 1,               // 当前段的第几轮（1 基）
    "loop_total": 3,         // 当前段总轮数
    "total_loops": 4,        // 整次编排的轮次总数
    "status": "playing",     // playing / paused / finished
    "finished": false
  }
}
```

- 提交成功即播放：`time` 为首段起点、`revision` 已 +1、`program.status="playing"`。
- 段尾跳回/跳段是瞬时跳转：随后 `GET` 看到的 `time` 是真实演出时码，`segment_index/loop`
  报告当前段与轮次；`server_wall/server_time` 仍是校时锚点（页面与服务端用同一份映射推算）。
- 全部走完：`playing=false`、`time` 为末段终点、`program.finished=true`、
  `program.status="finished"`（自动完成不加修订号）；此时再 `play` 从首段重演。

启用回路超载保护的房间，**超载段起点会拒绝整次编排**：

```json
{
  "error": "第 2 段起点 0.5 秒处 回路 #1「面光回路」 负载严格大于容量：该段起点已超载，整次循环排演被拒绝（本次未改动房间）",
  "reason": "overloaded_segment_start",
  "segment_index": 2,
  "time": 0.5,
  "circuits": [{"circuit_id": 1, "name": "面光回路", "capacity": 1500}]
}
```

错误情形（均不改变房间）：

- `403`：缺少/错误控制密钥（观看者无权编排或取消）。
- `400`：段列表不是 1～8 段的数组、某段不是对象、起点/终点为负数或非数字、
  `start ≥ end`、`end > duration`、`repeat` 不是正整数；启用保护时段起点超载
  （`reason:"overloaded_segment_start"`，附 `segment_index/time/circuits`）。
- `409`：修订号过期（与控制接口同一口径）；`404`：房间不存在；房间码格式错误 → `400`。

### 2) 播放过程中的控制（沿用既有 `/control`）

编排进行中，持密钥者照常调用既有控制接口（都携带当前修订号）：

```bash
# 暂停：当前段/轮/段内时码被固化（断点保留），修订号 +1
```

- **手动跳转取消编排**：`action:"seek"` 会删除编排，之后该房间回到普通房间语义

## 讨论停点 HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| PUT | `/api/rooms/:code/stops` | 整组替换讨论停点 `{control_key, revision, stops}`：一组不重复的非负时码（≤ 版本末尾），空数组 = 清除全部；成功修订号 +1，返回最新房间状态（含 `stops`） |

房间状态（创建 / 查看 / 控制 / 交接 / 停点提交响应一致）始终带 `stops` 块：

| 字段 | 含义 |
| --- | --- |
| `points` | 当前预置的停点时码（升序；空数组 = 未预置） |
| `next` | 未触发时给出：当前时码之后最近的停点 `{time, seconds_ahead}`（无则省略） |
| `tripped` | 仅自动暂停在停点时出现：`{reason:"stop_point", reason_text, time}`（重启后仍恢复；播放/跳转/清除后消失） |

### 2) 播放经过停点自动暂停

无需额外动作：服务端在 GET/控制的实时推算中自动截停。播放经过下一停点后：

```bash
curl http://localhost:3000/api/rooms/K7P2QX
```

```json
{
  "playing": false,
  "time": 12,
  "revision": 1,
  "stops": {
    "points": [12, 45.5, 90],
    "tripped": {
      "reason": "stop_point",
      "reason_text": "讨论停点已触发：播放连续经过预置停点，已自动暂停在此（自动暂停不增加控制修订号）；继续播放将越过该停点，循环排演每次重新经过仍会暂停",
      "time": 12
    }
  }
}
```

- `playing=false`、`time` 恰为停点时码、`revision` **不增加**（自动暂停与到末尾停住同一口径）。
- 继续 `play` 会**越过刚触发的停点**（不会在原地再停），到下一停点 `45.5` 再次暂停。
- 循环排演进行中：每轮重新经过段内停点都会再次暂停；段尾瞬时跳回/跳段不触发被跳过的停点。
- 与超载边界同一时码抵达时**超载优先**：响应出现 `protection.tripped` 而非 `stops.tripped`。

### 3) 错误情形（均不改变房间）

- `403`：缺少/错误控制密钥（观看者无权维护停点）。
- `400`：`stops` 不是数组、时码为负数/非数字、超过版本末尾、组内重复；
  修订号缺失/非法。整组校验失败则**整组不落库**。
- `409`：修订号过期（与控制接口同一口径），重新 `GET` 后用最新 `revision` 重试。
- `404`：房间不存在；房间码格式错误 → `400`。

## 定时启播 HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| PUT | `/api/rooms/:code/schedule` | 预约/覆盖定时启播 `{control_key, revision, start_at}`，仅暂停房间可预约，成功修订号 +1，返回最新房间状态（含 `schedule`） |
| POST | `/api/rooms/:code/schedule/cancel` | 取消待生效预约 `{control_key, revision}`，修订号 +1；无待生效预约 → 400 |

房间状态（创建 / 查看 / 控制 / 交接 / 编排 / 停点 / 预约响应一致）始终带 `schedule` 块：

| 字段 | 含义 |
| --- | --- |
| `state` | `"none"` 无预约且当前非预约启播 / `"pending"` 待生效 / `"started"` 预约已自动启播 |
| `start_at` | `pending`：预约的启播墙钟（Unix 秒）；`started`：实际启播墙钟 |
| `seconds_remaining` | 仅 `pending`：距启播的剩余秒数（不为负） |
| `from_time` | 仅 `pending`：启播时的断点演出时码（普通房间=当前时码/末尾则 0；编排=断点或首段起点） |
| `program_restart` | 仅 `pending`：已完成的循环排演将从首段重来时为 `true` |
| `reason_text` | 仅 `started`：启播结果说明（播放是否已结束另看 `playing`/`stops.tripped`/`protection.tripped`） |

### 1) 预约定时启播

`PUT /api/rooms/:code/schedule`，请求体 `{control_key, revision, start_at}`：

- `start_at`：**必填**的未来墙钟时刻，接受 **Unix 秒数**（数字或纯数字字符串）或
  **ISO 8601** 日期时间字符串（如 `"2026-10-03T19:30:00"` / 带时区的
  `"2026-10-03T11:30:00Z"`）；缺失/无法解析 → `400`。
- 时刻必须**严格晚于服务器当前墙钟**（等于当前时刻也算非未来）→ 否则 `400` 且房间不变。
- 仅**暂停的房间**可预约：房间播放中（含旧预约刚到点启播后仍在播放）→ `400`；
  0 时长（无 Cue）版本 → `400`。
- 启用超载保护时，启播断点（含已完成编排的首段起点）若**已处于超载区间**，预约被拒绝：

  ```json
  {
    "error": "预约启播起点 0.5 秒处 回路 #1「面光回路」 负载严格大于容量：启播起点不安全，预约被拒绝；请先在暂停状态下跳转到安全时码（本次未改动房间）",
    "reason": "overloaded_timecode",
    "time": 0.5,
    "circuits": [{"circuit_id": 1, "name": "面光回路", "capacity": 1500}]
  }
  ```
- 同一房间再次预约直接**覆盖**旧预约（只保留最近一次）；成功后修订号 **+1**，
  预约期间房间保持暂停。

```bash
# 方式一：Unix 秒（10 分钟后）
curl -X PUT http://localhost:3000/api/rooms/K7P2QX/schedule \
  -H 'Content-Type: application/json' \
  -d "{\"control_key\":\"d4e63d64…\",\"revision\":0,\"start_at\":$(date -d '+10 min' +%s)}"

# 方式二：ISO 8601 日期时间（按服务器本地时区解释，带 Z/偏移则按时区换算）
curl -X PUT http://localhost:3000/api/rooms/K7P2QX/schedule \
  -H 'Content-Type: application/json' \
  -d '{"control_key":"d4e63d64…","revision":0,"start_at":"2026-10-03T19:30:00"}'
```

成功返回（节选）即最新房间状态：

```json
{
  "code": "K7P2QX",
  "playing": false,
  "time": 12,
  "revision": 1,
  "schedule": {
    "state": "pending",
    "start_at": 1759491000,
    "seconds_remaining": 599.8,
    "from_time": 12,
    "program_restart": false
  },
  "server_wall": 1759490400.2,
  "server_time": 12
}
```

### 2) 到点自动启播（绝对墙钟，重启/迟到查询均准确）

无需额外动作：到点后下一次 `GET /api/rooms/:code`（或任意持密钥控制请求）会在一个事务内
完成**惰性启播 + 按预约墙钟推算 + 删除预约**，因此：

- 启播锚点是预约的**绝对墙钟** `start_at`：服务重启后、或首次查询已晚于预约时刻，进度仍
  **从预约时刻起算**，并准确停在**先遇到**的讨论停点、超载区间左边界或版本末尾。
- 自动启播**不增加修订号**；启播后 `schedule.state="started"`（附实际启播墙钟），
  下一次成功的手动控制清除该标记（`state` 回到 `"none"`）。
- 启播与删除预约同一事务，**绝不重复启播**（重复 GET 时码不会回退、不会二次锚定）。
- 启播起点规则与手动 `play` 一致：普通房间停在末尾则从 0 开始；进行中的循环排演从断点
  接续；**已完成的循环排演从首段重新开始**（预约块 `program_restart: true` 预告这一点）。

启播后查询的典型响应（到点较久，已停在版本末尾）：

```json
{
  "playing": false,
  "time": 20,
  "revision": 1,
  "schedule": {
    "state": "started",
    "start_at": 1759491000,
    "reason_text": "定时启播已执行：到点按预约的墙钟时刻自动播放（自动启播不增加控制修订号）；若播放已结束，则停在先遇到的讨论停点、超载边界或版本末尾。成功的手动控制会取消待生效预约并清除本标记"
  }
}
```

### 3) 取消待生效预约

```bash
curl -X POST http://localhost:3000/api/rooms/K7P2QX/schedule/cancel \
  -H 'Content-Type: application/json' \
  -d '{"control_key":"d4e63d64…","revision":1}'
```

- 删除待生效预约、房间保持暂停（时码/速度不变），修订号 **+1**。
- 已到点的预约会先惰性启播，再报 `400 当前没有待生效的定时启播预约`（启播不增加修订号）。
- 另外，**成功的 `/control`（播放/暂停/跳转/改速）、`/program`、`/program/clear`、
  `/stops` 都会隐式取消**待生效预约；主持权交接（`handover/claim`）**保留**预约。

### 4) 错误情形（均不改变房间）

| 情形 | 状态码 | 说明 |
| --- | --- | --- |
| 缺/错控制密钥 | 403 | 仅当前主持人可预约/取消 |
| 修订号缺失/非法 | 400 | 须为非负整数 |
| 修订号过期 | 409 | 房间不变，重新 GET 后用最新修订号重试 |
| 缺少/无法解析 `start_at` | 400 | 须为 Unix 秒或 ISO 8601 |
| `start_at` 不晚于当前墙钟 | 400 | `启播时刻必须是未来时刻…` |
| 播放中预约 | 400 | `房间正在播放：定时启播只能为暂停的房间预约…` |
| 0 时长版本预约 | 400 | 版本没有 Cue，无法启播 |
| 启播断点已超载 | 400 | `reason:"overloaded_timecode"`，附 `time` 与超载回路 |
| 取消时无待生效预约 | 400 | 从未预约 / 已被手动控制取消 / 已到点启播 |
| 房间码格式错误 / 不存在 | 400 / 404 | 与既有房间接口同一口径 |

观看者无需密钥 `GET /api/rooms/:code` 即可看到 `schedule` 块（待生效时刻、倒计时、启播结果），
但任何响应都**不含控制密钥**；观看者调用预约/取消均为 `403`。

| PUT | `/api/rooms/:code/stops` | 整组替换讨论停点（携带控制密钥与修订号）：不重复的非负时码、不超过版本末尾，空组 = 清除；播放连续经过即自动暂停并显示原因（不加修订号），修订号 +1 |
| PUT | `/api/rooms/:code/schedule` | 预约定时启播（携带控制密钥与修订号）：`start_at` 为未来墙钟（Unix 秒或 ISO 8601），仅暂停房间可预约、不安全（已超载）起点 400 拒绝，同房间只保留最近一次预约，修订号 +1；到点按绝对墙钟自动从断点播放（已完成的循环排演从首段重来），自动启播不加修订号，重启/迟到查询仍准确停在先遇到的停点/超载边界/末尾且不重复启播 |
| POST | `/api/rooms/:code/schedule/cancel` | 取消待生效定时启播（携带控制密钥与修订号），修订号 +1；成功的手动控制/编排/停点维护隐式取消预约，主持权交接保留预约，无待生效预约时 400 |

所有错误返回 `400/403/404/409` 与形如 `{"error": "具体中文原因"}` 的 JSON（`403` 用于共享房间缺少/错误控制密钥）。
